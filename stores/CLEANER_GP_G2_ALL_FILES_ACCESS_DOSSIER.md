## 1. Core functionality (честная формулировка)

NOVAX Cleaner — анализатор и очиститель хранилища Android: показывает,
что занимает место в памяти устройства, и освобождает место после явного
подтверждения пользователя. Основные сценарии (все — по всему общему
хранилищу /storage/emulated/0):

1. **Анализ кэшей приложений** — главный источник освобождения места
   (помечено в коде как «biggest impact», scan_service.dart:69-74):
   каталоги /Android/data/<pkg>/cache всех установленных приложений.
2. **Поиск дубликатов файлов** — по всему хранилищу (сравнение по
   размеру/хэшу), включая папки вне медиаколлекции.
3. **Поиск больших файлов** (>100 МБ) — по всему хранилищу.
4. **Старые загрузки и остаточные файлы** (Downloads, /Android/media
   неустановленных приложений).
5. **Очистка после подтверждения** — удаление найденного мусора
   (файлы перемещаются в корзину с восстановлением, не стираются молча).

## 2. Почему MediaStore недостаточен

1. MediaStore покрывает ТОЛЬКО медиа (фото/видео/аудио). Кэши приложений,
   временные файлы, загрузки, документы, остатки — вне MediaStore.
2. На Android 11+ MediaStore НЕ отдаёт файлы из Android/data|obb других
   приложений (restricted). А это главный сценарий клинера (кэши).
3. Наш продукт НЕ менеджер фото: удаление медиа через MediaStore — не
   наш сценарий, и декларировать его как основной было бы нечестно.

## 3. Почему SAF (Storage Access Framework) недостаточен

1. **Per-tree согласие.** SAF выдаёт доступ к ОДНОЙ папке за одно ручное
   действие пользователя в системном пикере. Для сценария «кэши всех
   приложений» нужно 50–150 отдельных согласий — core-функция мертва:
   ни один пользователь не пройдёт это, а показывать его бессмысленно.
2. **Android/data через SAF закрыт.** Начиная с Android 13 системный
   DocumentsUI блокирует выбор Android/data для сторонних менеджеров —
   даже ручное согласие не даст доступа к кэшам (проверено практикой
   линейки: SAF-пикер не открывает эти корни).
3. **Производительность.** SAF-обход — курсорный API DocumentsContract:
   нет stat() по путям, чтение метаданных порциями через query(). Полный
   обход хранилища (десятки тысяч файлов) через SAF — десятки секунд и
   риск ANR; прямой обход dart:io в изоляте (эталон Files: 6 759 файлов
   за секунды) — интерактивный сценарий «открыл → увидел, что съело
   память». Деградация убивает главный экран продукта.

## 4. Что деградирует без MES (главный аргумент К3)

| Функция | Без MES | Оценка ценности |
|---|---|---|
| Анализ кэшей приложений | НЕДОСТУПНА (Android/data закрыт) | ~50–70% пользы продукта |
| Дубликаты по всему хранилищу | Частично (без Android/data, Android/media) | Ключевая premium-фича |
| Большие файлы | Частично (без системных папок) | Ключевая premium-фича |
| Старые загрузки | Работает | Минор |
| Очистка кэшей после подтверждения | НЕДОСТУПНА | Основное действие продукта |

Без широкого доступа остаётся «очистка своих загрузок» — менее 20%
заявленной ценности. Приложение честно не сможет ответить на вопрос
«что съело память моего телефона» — а это его единственное назначение.

## 5. Что уже есть в продукте (соответствие требованиям G2)

- **In-app объяснение ДО системного экрана:** home_screen.dart:104,124 —
  поясняющий диалог перед переходом на экран «Доступ ко всем файлам»
  (объясняет зачем доступ, до того как система спросит).
- **Сценарий при отказе:** скан ограниченного объёма (без системных
  папок) + честное сообщение, что часть хранилища недоступна
  (permission_service.dart:8 — деградация задокументирована).
- **Узкий доступ:** MES запрашивается только на экране анализа, не при
  старте; приложение работает без него в деградированном режиме.
- **Удаление — только после явного подтверждения пользователя**,
  с корзиной и восстановлением (канон честности линейки).
