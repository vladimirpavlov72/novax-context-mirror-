## 1. Зачем это нужно

Пользователи всё чаще задают вопросы не поисковикам, а ИИ-ассистентам: ChatGPT с поиском, Perplexity, Gemini, YandexGPT, Bing Copilot. Чтобы ИИ рекомендовал приложения NOVAX, сайт novaxhub.ru должен:

- явно связывать **проблему пользователя** с **решением от NOVAX**;
- отдавать ИИ-ботам структурированную, легко «отщипываемую» информацию;
- содержать технические файлы-якоря: `llms.txt`, `robots.txt`, `sitemap.xml`, JSON-LD.

---

## 2. Как ИИ-инструменты находят и рекомендуют сайты

### A. Параметрическое знание (ChatGPT, Claude без поиска)

ИИ «знает» о бренде, если сайт и упоминания попали в обучающую выборку. Здесь работают:

- упоминания бренда в интернете (СМИ, блоги, форумы, отзывы);
- частота и консистентность описания;
- структурированность текста.

> NOVAX — молодой бренд, внешних упоминаний мало. Поэтому основной упор делаем на real-time поиск / RAG.

### B. Real-time поиск / RAG (Perplexity, Gemini, ChatGPT с поиском, Bing Copilot)

ИИ в момент запроса ищет релевантные источники и отвечает на их основе. Важно:

- интент пользователя должен совпадать с текстом на сайте;
- структура должна быть легко парсимой (заголовки, списки, FAQ);
- доверие: свежесть, каноничность, внешние ссылки.

Пример: запрос «в телефоне закончилась память, что делать» ИИ будет искать фразы «мало памяти», «очистить память», «освободить место». Если на сайте таких фраз нет — связи с Cleaner не произойдёт.

## 3. Какие файлы для ИИ нужны и что у нас есть

| Файл / элемент | Статус | Оценка |
|---|---|---|
| `robots.txt` | ✅ Есть | Базовый, нет отдельных правил для ИИ-ботов |
| `sitemap.xml` | ✅ Есть | Только главная страница |
| `llms.txt` | ✅ Есть | Хороший обзор, но нет интент-раздела |
| JSON-LD / Schema.org | ✅ Есть | Есть, но `description` у приложений слабые |
| `llms-full.txt` | ❌ Нет | Для глубокого погружения ИИ |
| `.md`-версии страниц | ❌ Нет | По спеке `llmstxt.org` полезно |
| `ai.txt` / Content-Signals | ❌ Нет | Пока экспериментально, не критично |
| Статический HTML | ✅ Ок | После `npm run build` сайт статический |

## 6. Важные правила работы с планом

### 6.1 Когда выходят новые приложения

**Каждое новое приложение NOVAX должно проходить через этот план перед добавлением на сайт.**

Это значит:

1. Для нового приложения собираются его ключевые интенты (минимум 10–15 источников боли).
2. Карточка на сайте получает problem-ориентированный подзаголовок.
3. `llms.txt` дополняется разделом «Если вы ищете...» для нового приложения.
4. JSON-LD обновляется: добавляется `MobileApplication` с `description` и `featureList`.
5. FAQ пополняется 1–2 типовыми вопросами по интентам нового приложения.
6. `sitemap.xml` обновляется, если появляются новые страницы/якоря.

> **Пример:** когда выйдет NOVAX Password Manager, перед публикацией карточки на сайте нужно задокументировать интенты вроде «где хранить пароли», «как не забыть пароль», «менеджер паролей без интернета» и добавить их в контент + разметку.

### 6.2 План живой, но не хаотичный

**Этот план не окончательный. Он должен улучшаться постоянно — но с умом, без выбрасывания ранних мудрых решений.**

Что это значит:

- **Добавляем** новые интенты, инструменты, форматы (например, `llms-full.txt`, отдельные лендинги, видео-скринкасты).
- **Проверяем** гипотезы измеримо: тестовые запросы до и после, валидаторы разметки, статистика упоминаний.
- **Не выбрасываем** проверенные решения: статический HTML, `llms.txt`, `robots.txt`, JSON-LD, problem-ориентированные подзаголовки — это база, которая работает.
- **Не гонимся за каждым новым стандартом** (типа `ai.txt` или Content-Signals), пока они не стали массовыми и понятными.
- **Обновляем** этот файл после каждого крупного изменения: что сделали, что сработало, что отложили.
