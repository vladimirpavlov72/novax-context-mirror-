## 2026-10-09 — Ценообразование: «якорь против подписки»; File Manager для GP; стратегия Cleaner

**Решения Владимира (после консультации Z, пакет reviews/z_consult_gp_files_launch):**

1. **Все пейволы (Habits/H₂O/QR, далее ФМ): честный якорь против подписки** —
   зачёркнутая «Подписка на год: $29.99» над живой разовой ценой $2.99.
   Фейковые старые цены запрещены (бренд честности). «Без денег и бизнеса не будет».
2. **NOVAX Files — НОВОЕ отдельное приложение для Google Play** (не ребренд
   Cleaner'а): пакет `com.novax.files`, лейбл «NOVAX Files». Fork моделей
   сканирования из Cleaner'а, UI с нуля. SAF + MANAGE_EXTERNAL_STORAGE
   (в заявке GP: «core = анализатор хранилища + управление файлами»).
   Очистка (cleaning) — только v2, в v1 слова «cleaner» нет. Flavors rustore/play
   с первого дня. Монетизация: тот же шаблон (trial 7 дней + $2.99 разово).
3. **Cleaner: НЕ в Google Play никогда.** Живёт на RuStore/Huawei/Samsung.
   SAF-адаптация НЕ нужна (SAF-клинер бесполезен); добавить
   MANAGE_EXTERNAL_STORAGE (альт-сторы выдают лояльно). Toolchain (3.24/SDK34)
   не мигрировать, пока сторы не потребуют.
4. **GP-запуск (после DUNS ~01.11):** путь internal → closed (3-5 тестеров,
   3-4 дня) → production (защита от авто-бана свежего орг-аккаунта).
   Privacy: одна страница novaxhub.ru/privacy/ (англ.). Data safety: финансовая
   инфо = да (история покупок, обработка Play). Play App Signing обязательно
   (подписи GP и RuStore будут разными — принято). Листинг en+ru, 4-5 скринов.
   **Порядок выкладки: QR → H₂O → Habits** (Habits ждёт фикс уведомлений).
5. **Монетизация:** цены не менять до данных GP. 0 продаж за 2 мес на RuStore —
   по Z это проблема ценности (0% конв. при ~100 визитов пейвола), не только
   трафика. Мерить: Play Console конверсия покупателей; <0.5% → менять модель.
   Trial 7 дней держать. Отзывы собирать через Play In-app Review API.
6. **Refund-политика (в реализации):** явный статус REFUNDED/CANCELLED отзывает
   локальный premium (GP-политика). Пустой список покупок premium не отзывает
   (защита от сбоев API) — без изменений.
7. **Уведомления Habits (блокер GP):** Samsung Adaptive Battery режет будильники
   sideload-приложений. Чек-лист Z: USE_EXACT_ALARM в манифесте, boot-reschedule
   receiver, кнопка-помощник «Уведомления не работают?» → настройки батареи.

**Почему:** сибестоимость проекта — тысячи $; 0 продаж за 2 месяца; GP — главный
тест монетизации. Z-variant 1 («якорь против подписки») — честная демонстрация
ценностей без маркетинговой грязи.

## 2026-08-08 — NOVAX Tone of Voice: только «ты», никакого «Вы»

**Решение:**

1. **Во всех приложениях NOVAX обращение к пользователю — исключительно на «ты» (неформальный тон).**
   - RU: «ты» вместо «Вы».
   - EN: неформальное `you`.
   - DE: `du` вместо `Sie`.
   - FR: `tu` вместо `vous`.
   - ES: `tú` вместо `usted`.
   - PT, IT, NL и другие — аналогично неформальное обращение.
   - Языки без категорического различия (JA, KO, ZH, HI, AR, TR) — сохраняем дружелюбный, прямой тон без излишней вежливости.

2. **Исключения:**
   - Юридические тексты (EULA, Privacy Policy), если официальный стиль требуется по умолчанию.
   - Иные случаи только по явному запросу Владимира.

3. **H2O:** `homeGreeting` в `app_ru.arb` изменено с «Оставайтесь бодрыми!» на «Оставайся бодрым!».

**Почему:**
- Единый дружелюбный стиль линейки NOVAX: приложения — как личный помощник, а не как банк/госуслуга.
- Консистентность между RuStore-описаниями, onboarding, UI и push-уведомлениями.
- «Ты» снижает психологическую дистанцию и лучше конвертит в B2C-приложениях.

**Действия:**
- [x] Обновить `AI_RULES.md` — добавить правило Tone of Voice.
- [x] Исправить `app_ru.arb` (`homeGreeting`) и перегенерировать `lib/l10n/generated/` в H2O.
- [ ] При ревью переводов других приложений (Cleaner, QR, Habits) проверить все строки на соответствие «ты»-стилю.

## 2026-08-08 — H2O v1.0.0+5: финальные спеки иконки и splash

**Решения (согласовано с дизайнером):**

1. **Adaptive-icon foreground:**
   - Фон: `#00AEEF` (уже в `colors.xml`).
   - Циферблат часов: белый `#EFEFEF`.
   - Обод часов: `#0369A1` (2–3 px).
   - Стрелки часов: `#0B4F6C`.
   - Фиолетовый градиент `#8C36CE → #4836F9` убирается полностью.
   - Стиль: flat, без PNG-блика, без многослойных градиентов; допустим один градиент воды `#00AEEF → #02D9EE`.
   - Safe zone: 66–70 % канваса 108dp.

2. **Splash-вектор:**
   - Форма: капля (не стакан).
   - Fill: `#38BDF8`.
   - Фон: прозрачный (подложку `#0B1220` рисует SplashScreen API).
   - Размер: 96dp × 96dp, viewport 96×96.
   - Один path, без групп/градиентов.

3. **Формат поставки:**
   - Adaptive-icon: PNG mipmaps mdpi–xxxhdpi + `icon_source.svg`.
   - Splash: `ic_splash.svg` + готовый `ic_splash.xml` (Android Vector Drawable).
   - Приоритет: сначала mipmaps и splash (блокируют сборку), потом SVG-исходники.

**Почему:**
- Белый циферблат + синий обод читается на mdpi лучше, чем монолитный синий круг.
- Капля в splash проще стакана, не рискует обрезаться маской и мгновенно узнаётся.
- Flat-стиль без глянца чётче на малых размерах.

   - Дизайнер возвращает `BLOCKER` / `WARNING` / `NICE-TO-HAVE`.

## 2026-08-08 — H2O: Z-ревью fixes перед релизом

**Решения:**

1. **Exact Alarm permissions убраны из `AndroidManifest.xml`.**
   - `SCHEDULE_EXACT_ALARM` и `USE_EXACT_ALARM` не нужны, так как `NotificationService` использует `AndroidScheduleMode.inexactAllowWhileIdle`.
   - Это снижает риск отказа на модерации RuStore и уменьшает потребление батареи.

2. **Premium не отзывается при пустом/временно недоступном списке покупок RuStore.**
   - `_syncPurchases()` проверяет локальный флаг `_premiumKey` перед сбросом `isPremium`.
   - `restorePurchases()` возвращает `true` только при реальной покупке, а не при активном триале.

3. **Ошибки биллинга локализуются через ARB-ключи.**
   - Сервис отдаёт код ошибки (`billingUnavailable`, `purchaseError` и т.д.), UI мапит код в локализованный текст.
   - Это позволяет держать сервис без `BuildContext` и соблюдать правило «нет хардкод-строк в UI».

4. **Сборка release APK выполняется с `--no-pub`, если `flutter pub get` зависает на сети.**
   - Пакеты vendored, повторный resolve не нужен.

## 2026-07-29 — H2O: подпись под иконкой и поисковая стратегия

**Решение:**

1. **Подпись под иконкой (android:label):** локализованный призыв + бренд `H₂O`:
   - RU: `Пей!H₂O`
   - EN: `Drink!H₂O`

   - DE: `Trink!H₂O`
   - FR: `Bois!H₂O`

   - JA: `飲もう！H₂O`
   - KO: `마셔요!H₂O`
   - ZH: `喝！H₂O`
   - HI: `पीओ!H₂O`
   - AR: `اشرب!H₂O`
   - TR: `İç!H₂O`

2. **Карточка RuStore:** сохраняем паттерн `NOVAX H₂O — дескриптор` (`NOVAX H₂O — трекер воды`). Призыв остаётся в описании/слогане.

3. **Поисковая оптимизация:** пользователи ищут обычную `2`, а не subscript. В keywords добавляем: `H2O`, `H 2 O`, `H20`, `н2о`, `н20`, `н 2 о` + локализованные ключи.

4. **В описании:** упоминаем оба варианта — брендовый `H₂O` и поисковый `H2O`. Пример: `NOVAX H₂O (H2O) — трекер воды...`

- Но ввод с клавиатуры subscript не поддерживается, поэтому в поиске доминирует обычная `2`.
- Локализованный призыв (`Пей!`, `Drink!`) — это CTA внутри имени, усиливает конверсию и запоминаемость.

**Действия:**

## 2026-07-27 — Цветовая система линейки NOVAX

**Решение:** Один продукт — одна цветовая идентичность, покрывающая И иконку, И UI-акцент приложения. Стиль единый (flat, минимализм), цвета разные. Существующие приложения НЕ перекрашиваем.

**Почему:** Цвет — функциональный маяк (пользователь ищет «зелёное» на рабочем столе). Семья узнаётся стилем, не одной краской. UI внутри приложения должен продолжать цвет иконки — как уже сделано в QR (navy + бирюза в paywall).

**Практика:**
- Cleaner — Green `#34A853`.
- QR Scanner — Teal `#2DD4BF` на базе Ink navy `#0E1E38`.

## 2026-07-27 — Windows Developer Mode и VPN

**Решение:** Developer Mode в Windows (`start ms-settings:developers`) необходим для Flutter-проектов с плагинами, потому что Flutter использует symlinks при сборке. Без Developer Mode `flutter pub get` / `flutter build` падает с ошибкой `Building with plugins requires symlink support`.

**Почему:** Windows блокирует symlinks для не-привилегированных приложений, пока не включён Developer Mode.

**Важно:** Developer Mode может "отваливаться" без активного VPN. Если после перезагрузки/смены сети сборка снова падает на symlink — проверить: (1) Developer Mode всё ещё ON, (2) VPN активен.

**Практика:**
- Включить Developer Mode один раз и держать включённым.
- При странных ошибках сборки сначала проверять Developer Mode + VPN.
